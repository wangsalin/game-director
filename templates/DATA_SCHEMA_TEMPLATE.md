# Data Schema and Save Contract

> 写作说明：按实际语言/引擎定义可执行的数据约束；示例对象标明示例，不夹带用户存档或凭证。LITE 可合并入 TDD。

## 数据实体

| 实体/字段 | 类型/单位 | 默认值 | 必填/范围/枚举 | ID/引用约束 | 存档/临时/权威端 |
|---|---|---|---|---|---|

区分静态配置、单局状态、长期进度和平台数据；写空值、未知 ID、非法数值与缺配置的处理，不能只列字段名。

存在叙事系统时登记任务/对白/线索/结局的稳定 ID、条件变量类型/初值/作用域、读写事件、角色知识与奖励去重键。定义选择提交、回看/跳过/重进、保存恢复及删除/改名节点迁移；世界事实、玩家已知与角色已知不可混成同一布尔值。不适用则省略。

## 状态与事务

列关键状态转换、库存/奖励/扣费的提交边界和重复请求行为。联网项目明确客户端可提交内容与服务端校验，单机不为形式增加服务端。

## 存档与迁移

版本字段、保存时机/位置、失败与损坏恢复、旧版本兼容、迁移步骤、备份和回退。时间相关规则明确可信来源、回拨和离线策略。迁移前核实环境，不用生产数据做测试。

## 验证用例

覆盖有效对象、缺失字段、无效引用、极值、截断存档、跨版本、保存中断和重复提交；每项有预期结果，未实现迁移不能声称兼容。
