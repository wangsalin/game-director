# 引擎开发路由与验收

仅在任务涉及引擎选择、工程开发、导入、排错或构建时读取；策划、故事背景和局部资产讨论不强制加载。先核实已有工程，再只读命中的专项：

| 工程 | 读取 | 识别依据与注意 |
|---|---|---|
| Godot | [Godot](godot.md) | `project.godot`；区分 3/4、标准/.NET，配置里的功能版本不等于精确补丁 |
| Unity | [Unity](unity.md) | `ProjectSettings/ProjectVersion.txt`、`Assets/`、`Packages/`；不能用 Hub 版本代替 Editor 版本 |
| Unreal Engine | [Unreal](unreal.md) | `.uproject`；`EngineAssociation` 可能是自定义构建标识，不一定是版本号 |
| Cocos Creator | [Cocos Creator](cocos.md) | 3.x 看 `package.json` 的 `creator.version`；旧 2.x 常见 `project.json`；应用版本不是编辑器版本 |

没有工程时依据[技术选型](../technical-planning.md)和用户平台选引擎；指定引擎时保留选择。支持专项表示有操作指导，不表示环境已安装、任意平台可导出或本项目已验证。Cocos2d-x 不等于 Creator；其他引擎按其对应版本官方工作流处理，不套用这些命令。

## 只读工程识别

可从任意工作目录运行[识别工具](../../scripts/inspect_engine_project.py)，也可直接检查相同元数据：

```text
python -B "<skill-dir>/scripts/inspect_engine_project.py" "<actual-project-root>"
```

工具仅读取根目录标志和选定配置，输出 JSON，不启动引擎、不安装 SDK、不写入工程、不执行工程脚本。退出 `0` 只表示识别到一个工程且所读元数据没有错误；`1` 表示未识别、歧义或元数据错误；`2` 表示参数用法错误。警告需要人工核实，所有编辑器/导入/编译/试玩/构建/产物启动/设备阶段默认 `not_run`。多引擎或多个 `.uproject` 不擅自选一个；将路径收窄至本次实际工程。损坏的普通 npm 配置不是 Cocos 识别证据。工具不审查完整资源、场景引用、SDK、插件或所有旧版工程；回归范围见[测试](../../scripts/test_inspect_engine_project.py)。

## 实施前的最小环境记录

记录工程根目录/当前提交、精确 Editor 版本与来源、可执行文件路径、宿主系统、语言/渲染后端、目标平台、已有依赖/插件及锁文件。先查 PATH、项目文档、引擎管理器和相关安装位置；不要全盘遍历用户数据。通过受控的版本查询或编辑器 About 核实实际二进制，不能因某个路径存在就声称可用。

编辑器缺失不自动获得升级工程、接受新许可、登录账户或下载庞大工具链的授权。可继续规则/代码/元数据审查，列最小解锁条件；允许安装时使用官方来源，固定版本并验证下载摘要，放在约定位置，不修改无关全局设置。打开未知工程可能运行插件/导入脚本，不把“只读识别”变成启动。

已有工程先保留 Git 差异和恢复点，在匹配版本打开；首次导入、包还原、场景/资产升级可能改文件，导入后核对差异。不能用升级、清缓存、重建场景或重新生成 `.meta` 掩盖真正问题。

## 从工程到可验证切片

1. **创建/导入**：新项目用目标版本原生模板；已有工程沿用入口、依赖和目录，等待导入完成，先处理日志中的首个根因。
2. **最小可玩场景**：连接真实输入→规则状态→可见反馈，包含目标/结束或持续进度、重开和适用的暂停/保存。创建脚本不等于脚本挂载、对象引用和入口场景配置完成。
3. **代表性资产**：导入一组实际素材，检查尺寸/坐标/单位、锚点、碰撞、材质/着色器、动画、音频和引用；用[资产规范](../asset-production-spec.md)裁剪，不先批量扩产。
4. **编辑器运行**：真实操作核心循环，检查控制台、丢引用、重复事件、暂停/场景切换与资源释放；单元测试和无头测试不能替代图形/输入检查。
5. **目标构建**：固定实际平台、场景/地图、预设、输出目录、SDK/模块与插件；输出到专用目录，不覆盖源码或旧失败证据。只运行当前任务授权的构建阶段，打包不自动上传商店。
6. **启动产物**：从实际输出独立启动，不依赖编辑器会话；验证首次加载、核心行动、结束/重开、保存和资源。Web 核实 HTTP、压缩头、WASM/MIME、跨源隔离等所需条件，不能只看 `index.html` 存在。

复用[原型验收](../prototyping.md)的证据方法，输入方式必须覆盖实际玩法。普通静态浏览器工具不能默认接管原生窗口、指针锁定或任意引擎导出；用项目自身测试/真实操作补足。

## 证据和交接

在 [TDD](../../templates/TDD_TEMPLATE.md)和[开发入口](../../templates/CODEX_START_HERE_TEMPLATE.md)写实际版本、入口场景/地图、依赖恢复、工作目录、构建命令/配置和阶段结果；把本项目需要的步骤留在工程内，接手者不能只拿到 Skill 绝对路径。

| 阶段 | 通过所需证据 | 不能替代的内容 |
|---|---|---|
| metadata | 实际配置与只读检查结果 | 编辑器/SDK 已可用 |
| import / compile | 对应版本日志、退出状态及错误检查 | 可玩性、渲染正确 |
| editor-play | 实际核心行动、预期/实际、截图或录像、错误日志 | 独立构建可启动 |
| build | 构建配置、日志、该工具的成功判据、实际产物 | 产物正常运行 |
| artifact-run | 对应产物哈希/提交、启动和流程证据 | 所有目标设备通过 |
| device | 具体设备/系统、安装包、操作/性能证据 | 所有设备或发布通过 |

每阶段使用 `passed / failed / not_run`，注明时间、环境、命令/操作、证据相对路径。进程返回码必须按对应引擎版本解释；例如 Creator 3.8 的构建成功码不是通用的零。缺编辑器、模板、编译器、设备或渠道条件时保留 `not_run` 和最小解锁条件；资源包导出、原生可执行构建、浏览器预览、小游戏模拟器与真机分别记录。
