# 游戏 UI/UX 设计与验收

按[UI 模板](../templates/UI_SPEC_TEMPLATE.md)交付可实现规范。先判断真实输入方式与游戏节奏，再选择布局；不能把普通后台界面风格直接套在游戏 HUD。

## 页面与流程

建立页面/弹层 ID、入口、出口、返回行为和可达条件。按游戏需要覆盖菜单、选关、HUD、背包/角色、升级/构筑、暂停、结算、设置；不需要的页面不新增。列出首次进入、开始一局、失败/重试、胜利、退出/续玩等真实路径，防止无返回和死路。

HUD 标注战斗时必须常驻的信息与可展开信息；触屏时避开手指遮挡和系统安全区，键鼠/手柄说明焦点与导航。暂停、升级选择和结算是否停止时间，必须与规则一致。

## 视觉规格

- 目标分辨率、横竖屏、参考设备、安全区、UI 缩放方式与极端比例降级规则。
- 字体/中文回退、字号层级、颜色语义、间距、按钮命中区域、图标尺寸、状态优先级。
- 功能状态包含可用、按下、选中、禁用和实际存在的加载/失败/空数据；离线单机不强加联网加载页。
- 动画时长、可打断条件、输入锁定、反馈与音效；快速连点、重复提交和返回键的规则。
- 信息不只靠颜色表达；考虑文字缩放、字幕、闪烁/震屏开关和操作替代，按平台与范围选择。

## 原型

当用户需要高保真或视觉风险明显时，用当前可用的前端/设计工具做可检查原型，标注 `design_reference` 或 `production_ui`。参考原型的演示数值必须标为示意，不冒充真实保存/联网结果。生产界面复用真实状态和输入，不保留演示成功提示。

只做文案或流程评审时，不擅自生成代码原型。无法运行浏览器或引擎时报告未验证范围，提供具体布局和交互规格。

## 验收

实际打开可运行页面/场景，走一遍核心路径并检查错误输出；在目标屏幕看中文、截断、安全区和层级。输入方式覆盖当前支持的触控、键鼠或手柄；检查双击、弹层叠加、暂停/恢复、失焦及屏幕变化。记录原型路径、运行环境、观察和未测设备。
