# 生产阶段与验收

阶段代表证据逐步成熟，不要求每个请求走完流程。没有开发授权时，灰盒和切片阶段只写计划，状态保持未验证；交付文档时明确是“策划就绪”。

| 阶段 | 进入条件 | 最小交付 | 退出证据 |
|---|---|---|---|
| 01 创意/研究 | 创意或研究目标 | 体验假设、必要参考、来源与未知项 | 事实可追溯；没有虚构试玩、销量或市场结论 |
| 02 立项 | 足以形成方向的信息 | Brief、MVP/不做清单、资源约束、决策 | 可逆选择有确认/委托/假设标记；重大范围冲突解决 |
| 03 规则/技术探针 | MVP 边界清楚 | 状态/规则、可计算例子、风险清单、引擎候选 | 能描述完整一轮操作及结果；高风险平台能力已核实或列为阻断 |
| 04 灰盒 | 实施授权、规则和必要运行工具 | 可玩核心循环、临时资产标记、验证记录 | 真实输入可重复完成胜负/结算；边界不破坏规则；体验反馈有来源 |
| 05 UI/风格 | 核心流程稳定，或明确仅做设计提案 | 页面流、HUD/状态、风格规范、必要视觉原型 | 关键流程可走通；目标屏幕可读；设计参考与生产界面标识清楚 |
| 06 代表性切片 | 灰盒通过、视觉/技术方向可行 | 少量正式资产、导入记录、代表场景 | 玩法/UI/资产共同运行；预算与设备证据达到本阶段目标 |
| 07 生产交接 | 范围与关键风险已明确 | 自包含入口、架构/数据、清单、里程碑/QA | 每项需求对应实现位置或计划与验收；未解决条件明确 |
| 08 内容开发 | 核心循环与切片达到扩产条件 | 按里程碑扩展系统、关卡、资产和平台能力 | 每个里程碑可运行；状态、文档、缺陷与资产同步 |
| 09 QA/优化 | 目标功能可验收 | 测试报告、缺陷复测、性能/兼容证据 | 达到约定退出标准；未执行设备/平台测试明确列出 |
| 10 发布准备 | 候选构建与渠道条件明确 | 构建、发布清单、授权核验、存档兼容/恢复方案 | 目标渠道条件逐项核实；实际提交/发布另有对应授权 |

## 四种就绪结论

- **策划就绪**：实现所需的决策、规则、界面和验收足够明确；核心体验可以仍未实测，必须标明“原型待验证”。
- **原型已验证**：真实操作与记录支持核心规则可运行；仅模拟测试时不声称目标设备通过。“好玩”必须说明体验者和反馈依据。
- **生产就绪**：玩法与代表性资源/技术切片通过约定门槛；才能安排大量关卡、模型、动画和音频生产。
- **发布就绪**：候选构建达到目标平台约定验收；没有真机或渠道验证时只能报告剩余缺口，不能自动升级结论。

## 并行与例外

早期可做少量风格探索、性能探针或 UI 提案，但必须限制数量/预算并标记假设，不能以此绕过灰盒验证批量生产。已有项目直接用现有证据定位阶段，不倒退重做。对微型游戏，灰盒/切片可能很快合并完成，但退出证据仍需真实。

失败时记录具体观察、受影响假设和下一项最小实验；先回到规则或技术瓶颈，不通过继续堆素材掩盖玩法问题。涉及重大方向变更时引用[续接与变更协议](project-continuity.md)。
