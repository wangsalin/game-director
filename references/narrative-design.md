# 故事、世界观与叙事制作

用于游戏故事背景、世界观、角色/势力、主支线、对白、环境叙事及已有剧情审查。先确认当前只需设定讨论、文档创作还是实现；只改剧情不会自动授权重做玩法、制作素材或编写游戏代码。

## 选择叙事份量

先复用类型、核心循环、受众、题材、情绪、内容边界、时长和预算。只有缺失项会显著改变故事方向时才问一个关键问题；其余可逆选择按已有委托继续并记录，不重新问完整立项问卷。

| 需求 | 最小合适产物 | 不必展开 |
|---|---|---|
| 只要故事背景/主题包装 | 一句话前提、玩家身份与行动理由、当前危机、关键世界规则、玩法联系 | 完整对白树、任务数据库、角色百科 |
| 轻叙事 | 背景 + 少量角色/事件 + 开场/转折/结尾与局内信息投放 | 大量支线、多结局、复杂好感度 |
| 剧情驱动 | 世界/角色设定、可玩章节与主支线、对白/状态契约、预算和叙事 QA | 未经需求确认的开放世界、全配音或无限分支 |

叙事份量与 LITE/STANDARD/PREMIUM 独立：短篇单房悬疑可以有精确叙事，体量大的竞技游戏也可以只有背景。只做叙事局部交付时不强制整套项目文档/资产清单；需要制作交接时才把实际叙事资产并入项目清单。

按需使用[背景/世界设定](../templates/STORY_BIBLE_TEMPLATE.md)、[角色与势力](../templates/CHARACTER_BIBLE_TEMPLATE.md)、[故事大纲](../templates/STORY_OUTLINE_TEMPLATE.md)、[任务设计](../templates/QUEST_DESIGN_TEMPLATE.md)、[对白与演出](../templates/DIALOGUE_SCRIPT_TEMPLATE.md)。LITE 可合并为 GDD/README 的具体章节，只有当前请求需要的模板才读取和生成。

## 原创方向与故事前提

已有明确方向就展开；仅在用户需要探索时给少量有区别的方向。每个方向说明玩家身份、欲望、阻力、失败代价、情绪与核心行动，不只给题材标签。参考作品拆解体验与手法，人物、地名、对白、关键事件和专有视觉表达原创；改编已有 IP 时先记录授权边界。虚构设定无需伪装为历史事实；采用真实历史/民俗/科学主张时核实来源，明确艺术改写。

故事开头应能回答：玩家是谁、为什么现在行动、反复进行核心操作为什么合理、失败/重试在故事中如何理解。纯玩法重试可以是非叙事约定，不强行发明轮回设定。主题用可选择的冲突表达，不用旁白替玩家下结论。

## 世界、历史与信息边界

- 只设定影响行动的时代、地点、科技/魔法规则、资源/权力、风俗与禁忌；规则写能力、限制、代价与例外，不能到结尾临时增加万能能力解围。
- 世界背景先写真实发生了什么、为何形成当前局势、各方得失；时间线注明相对/绝对时间、因果与在场者，区分正史、传闻和角色误解。
- 势力的目标、控制资源、正当理由、内部矛盾和对玩家的态度要能推动任务；不为所有小故事强造国家、宗教和千年史。
- 建立作者真相/玩家已知/角色已知的区别。关键揭示写最早可得信息、载体/场景、必要前置与后续回收；不让 NPC 提前泄露未知，不让角色凭空知道玩家未传达的事。
- 悬疑线索区分事实、推断和误导。关键推理的证据必须在结论前可获得；允许多路径获取必要信息，错过可选线索也能理解主线。误导回收需解释依据，不靠隐藏必需事实制造假公平。

## 角色与势力

主角/关键 NPC 写目标、动机、能力与局限、对失败的恐惧、关系中的利益和变化；背景经历只保留影响当前选择的部分。玩家扮演固定角色还是自行塑造角色必须一致，不替开放扮演强写与选择冲突的动机。

角色弧线包含起点信念、被玩家行动触发的冲突、关键选择、付出代价与可能终点；反派也有可理解的目的与行动因果。重要 NPC 有自己的行动计划，不能只站着发任务。对话标识语气、词汇/句长、避讳、知识边界和一小段实际示例，避免全员同一种作者腔。

角色视觉轮廓、道具/动作线索连接 Art Bible；角色声音连接音频需求。角色设定/立绘不意味着模型、配音或演出已经制作。

## 主线、支线与可玩的节拍

按实际作品组织开场承诺、触发事件、目标/阻碍、推进、转折、高潮与收束，不强制三幕公式。每个关键节拍写玩家做什么、通过什么交互获得信息、失败后怎么办、世界状态如何变；避免连续长过场代替全部可玩行动。

支线说明主题/角色/玩法作用、进入/退出时机、与主线的依赖及错过后的处理。删掉支线不会让必经主线无解；可选内容不偷偷成为唯一关键线索。线索/伏笔按设置→加强→揭示/回收关联，不能用“后续补充”掩盖当前承诺没有结局。

分支注明是对白差异、状态差异、路线分歧还是不同结局，何处合流、哪些后果保留；不要承诺每个选项都生成整章独立剧情。选择前提供足够可理解的信息；相同后果的风味选项可以存在，但不能包装成并不存在的永久大分支。结局写互斥/优先级、达成条件与玩家可理解的因果；未决时补上默认/无匹配处理。

## 任务、对白与数据交接

沿用项目已有引擎/对话工具和数据格式，不因叙事需求引入新框架。尚无实现时用自包含规格，不编造已存在 API 或制作“能直接运行”的假导出。需要结构化内容时按实际工程约定 ID、字段类型、条件表达式与副作用语义。

- 稳定 ID 连接角色、地点、任务、场景/节拍、对白节点、线索、物品与结局；名字可改，存档引用不能随意改。权威世界规则只维护一份，其余引用。
- 任务写接取/激活、进行、条件满足、提交/失败/放弃/重试、互斥与收束；目标如何计数、预先持有物品/提前完成目标如何处理。道具扣除、奖励和关键变量一次提交，重复交互/载入不重复发奖，背包满和前置角色离场有确定路径。
- 对白节点写说话者、进入条件、实际台词、本地化键、可选项/禁用理由、目标节点/终点、状态修改与触发时机。先定条件再列可选项；节点没有合法选项时有明确收束/回退，不能软锁。
- 读档/回看/跳过对白/自动推进不能重复副作用，也不能漏掉必需信息与任务状态；表现播放和任务提交分开。已获得关键信息可回看，跳过过场仍能知道下一目标。
- [数据契约](../templates/DATA_SCHEMA_TEMPLATE.md)登记变量类型、默认值、作用域（节点/任务/局内/长期）、读写节点、保存点与旧 ID 迁移。角色知识与任务变量只在真实事件发生后变化，不能用“已读到某句”推断并未提交的选择。

## 文本、演出与生产预算

指定叙述视角、时态、中文语体、专名词表和内容边界。用户要求成稿时交付实际背景文本/场景/对白，不能只给模板或剧情占位句；大体量任务按已授权章节交付，不把局部试写标成全剧本完成。

规划字幕说话者、中文换行/文本缩放、逐字显示/跳过/回看、关键音效提示、过场接管与归还控制权。语音是可选生产需求，未录制就标待制作；静音和跳过动画仍保留必要信息。对白长度/阅读时长为估计，最终在实际界面和目标玩家试读。

按唯一场景、节点、选项、字数/词数、配音语言、插画/动画/关卡需求估算。分支预算统计唯一内容和各路线必经内容，不把共享节点重复算作独立章节；记录可复算的数量依据。先完成一段可检查的叙事切片，再扩写大量对白或批量生产演出素材。

## 审查与验收

先做文档中的因果/时间线/角色知识一致性与路线走查；结构化数据已经存在时，可用项目工具或临时脚本验证 ID/引用、条件、状态和可达性，不为纸面故事硬建运行时。

| 检查 | 最小可观察标准 |
|---|---|
| 背景与玩法 | 角色目标、当前危机和反复核心行动彼此支持；关键世界能力/限制没有自相矛盾 |
| 情节与信息 | 每个必经转折有前因/可得线索；角色获得信息有事件依据；可选内容缺失不使主线无解 |
| 分支与结局 | 用入口→具体选择/变量→终点的路线表走查；考虑互斥、无匹配与重进；静态图可达不等于条件同时可满足 |
| 任务与存档 | 预持道具、先后顺序、失败/重试、重复提交、跳过/回看、读档与角色离场均有明确预期 |
| 制作与文本 | 实际写作数量、依赖资产和预算可核对；本地化键与角色口吻明确；中文、字幕/跳过等运行结果据实记录 |

项目 QA 追加适用用例，并记录是纸面检查、脚本检查、试玩还是设备验证。未运行节点/引擎/设备时保持 not_run；纸面连贯不等于对白好读、谜题公平或体验好，后者需有对象、版本与实际反馈。现有 `validate_project.py` 面向带资产清单的项目，只检查文档链接/资产文件，不解析故事内容、剧情图或任务语义；纯叙事局部交付不适用，按[项目文件验收](project-validation.md)的范围说明处理。

续写或改设定时先读当前正史、时间线、角色知识、进度/决策及已确认结局；标明受影响的对白/任务/资产/本地化/存档与失效测试，保留旧决策和 ID 迁移，不静默改写已发布事实。按[续接协议](project-continuity.md)管理变更。
