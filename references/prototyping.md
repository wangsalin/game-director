# 可玩原型、运行验收与继续开发

用于用户明确要求做原型、实现可玩版本或继续开发已有原型的任务。讨论想法、写策划、故事或只读评审不自动获得编码、启动服务、安装工具或发布授权。

## 先选择当前路径

1. 先读当前工程/规则、适用指令、Git 差异、已有测试和实际运行方式。用户指定的引擎、平台与已验证玩法优先，不能为使用底座切换技术栈。
2. 没有工程且已授权实施时，只补问影响核心行动、平台和范围的关键缺口。可逆细节按委托决定；先明确这次要验证的玩家行为/反馈、可观察结果与暂不做内容，不先写整套大型 GDD。
3. 轻量 Web 合适且用户没有相反选择时，可用下述底座；已有 Web 用现有框架，原生引擎用真实编辑器/构建流程。缺引擎、导出模板、设备或凭证时明确阻塞与未运行范围，不能用浏览器页面冒充对应引擎构建。

## 可选 Web 底座

工具入口：[创建脚本](../scripts/create_web_prototype.py)、[底座说明](../assets/web-prototype/README.md)、[配置](../assets/web-prototype/config.js)、[规则](../assets/web-prototype/src/rules.js)、[输入/渲染](../assets/web-prototype/src/main.js)、[页面](../assets/web-prototype/index.html)、[样式](../assets/web-prototype/style.css)、[项目配置](../assets/web-prototype/package.json)、[规则测试](../assets/web-prototype/tests/rules.test.js)、[浏览器计划](../assets/web-prototype/browser-plan.json)。

```text
python -B "<skill-dir>/scripts/create_web_prototype.py" "<new-project-dir>" --title "项目名称"
```

目标父目录须存在，目标目录须不存在；脚本拒绝覆盖现有工程，若复制中断可能留下新的部分目录，应先检查而非盲重试。脚本只复制自包含项目、测试和验收工具，不安装依赖、启动服务或预填验证通过。

生成项目附带 [.gitignore](../assets/web-prototype/.gitignore)，忽略本地依赖/缓存/凭证和默认临时验收目录，不隐藏源码、锁文件或正式证据。保留失败报告；需要纳入版本的证据按项目约定选择目录，不能为保存报告而把依赖和本地环境配置一起提交。

底座是实际可玩的回合制收集游戏，用于已有机制可复用的起点或工具试跑。用户要其他玩法时必须改写对应规则、输入/反馈及用例；只改标题不等于完成用户游戏。几何图形为临时素材。底座用 ES 模块，本地 HTTP 运行；不承诺双击 HTML 可用。它不覆盖 3D、物理、多人或小游戏 SDK。

Python 创建/文件校验只用标准库；底座运行只需要浏览器和静态 HTTP 服务。Node 20+ 用于规则测试。Playwright 1.65.1 只用于可选自动浏览器验收，通过工具内锁文件安装；不写进游戏运行依赖，不改用户全局配置。检查当前工具/可用 Skill，按其说明操作。安装工具不代表游戏已通过验证。

## 实现与调参

把核心规则、可调参数、输入/渲染、保存边界分开到当前项目足够维护的程度。规则测试从已确认机制推导准确预期，不用渲染 DOM 承担所有规则测试；存档、异步和浏览器交互仍须在对应环境检查。

先让一次真实操作产生可理解反馈，并能推进核心循环，再扩展内容。调参保留参数单位、限制和理由，关键派生值复算。原型允许少量临时资产，制作清单与生产检查按范围裁剪；不能为了通过整项目资产脚本增造资源。

## 运行与实际证据

先运行项目已有测试、构建和启动命令，再实际进入游戏。按当前玩法验证入口、核心行动、结算/目标、失败或其他退出、重开与适用的暂停/存档；持续型游戏按真实进度与重置规则，不强加胜负系统。需求中存在的键盘、鼠标、触控分别检查。

静态 Web 可用[浏览器检查器](../scripts/web-check/check.mjs)，格式/退出码/边界见[工具说明](../scripts/web-check/README.md)，依赖用[package.json](../scripts/web-check/package.json)与[锁文件](../scripts/web-check/package-lock.json)。创建脚本已把工具复制进新项目 `tools/web-check/`，接手者不依赖安装本 Skill。

```text
node --test tests/rules.test.js
npm --prefix tools/web-check ci
node tools/web-check/check.mjs --project . --plan browser-plan.json --out evidence-run-01
```

默认用 Playwright Chromium，可改用已安装 Chrome/Edge 或实际可执行文件；缺包/浏览器输出 not_run 与退出 2。环境具备时才运行。已有项目先按实际构建到静态输出目录；不要把后端源码、整个工作区或原生工程当作静态产物交给工具。

先按工具说明核对资源/服务器/输入条件：支持未压缩 WASM 和部分游戏二进制/Ogg 资源，不保证任意引擎 Web 导出可运行；压缩响应、跨源隔离、专用加载器及持续按键/鼠标移动/拖拽等输入应使用已验证的项目自身工具。所需条件缺失时记录阻塞，不以简化网页或单次操作冒充原平台/操作验收。

计划必须来自本项目规则：初始条件→真实点击/键盘/触控→明确断言→截图。空计划和只有截图没有断言的场景不能通过。可选只读观测口 `window.game.getState()` 返回真实状态快照；不提供设置位置/库存、强制胜利的测试捷径。没有观测口可用实际 DOM 断言，复杂 Canvas 按项目最小需要增加观测，不重写游戏来迁就检查器。

检查器记录逐步结果、错误、浏览器/视口、计划和已服务文件的哈希、截图；每次写入新目录，不覆盖失败证据。改了代码/资源后旧结果不代表新版本，修复后新目录复测。保留失败报告、原因和复测对应关系；检查失败不通过删除断言、修改真实状态或降低验收标准解决。

自动结果只覆盖对应计划。打开/查看实际截图，检查中文、布局、HUD、开始/失败/结算、可读性和窄屏；根据需要手动试操作与控制台。触摸模拟不等于实体手机测试，固定输入路线不等于玩法平衡或玩家觉得好玩。截图成功、进程退出 0、生成了按钮都不能单独证明游戏可用。

区分规则测试、浏览器用例、视觉检查、编辑器、导出构建、实体设备和玩家反馈；未执行保持 not_run。缺硬件/软件/依赖时记录最小解锁条件，继续不受影响的检查；同一方法没有新证据时停止重复重试。修复与复测聚焦当前授权范围。

## 从原型继续开发

继续使用当前可运行工程，先保留 Git 恢复点和已有数据。记录当前验证的问题、规则/参数、临时资产、文件职责、准确命令和环境，把报告/截图的真实相对路径加入 README 与开发入口。

按下一里程碑需求拆模块、增加构建工具、替换资源或迁入用户确认引擎，保留玩法和测试的可复核对应。变更规则、输入、存储、引擎或资产后标记受影响的旧测试，执行对应复测；不为整齐重建工程、静默改变规则或一次上完整框架。

交接包括：本次原型假设与实现范围、可玩工程入口、启动/测试步骤、实际报告与环境、已知缺陷/临时素材、未运行项、下一里程碑及授权边界。使用[开发入口模板](../templates/CODEX_START_HERE_TEMPLATE.md)，不能把本机 Skill 绝对路径设为唯一运行/验收方式。本版提供可继续开发的模块化 Web 底座和工具，不宣称任意游戏到任意引擎的自动迁移。

## 维护验收

[创建回归](../scripts/test_create_web_prototype.py)检查新目录、资源、拒绝覆盖与异地调用；[浏览器工具回归](../scripts/web-check/check.test.mjs)检查无断言拒绝、路径/静态服务、失败报告与缺工具 not_run。原型规则测试与真实浏览器用例另行执行，结果写入[行为验收记录](validation-scenarios.md)，不能用维护测试替代游戏验收。
