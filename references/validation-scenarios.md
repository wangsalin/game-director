# 行为验收场景

用于安装后或大改后的真实对话评估。下面是测试输入和可观察标准，不是已通过的测试记录。每个场景在独立上下文中运行；恢复场景在临时项目使用预先准备的真实文件。不要在生产工程或付费服务上试验。

## 场景与观察

| 场景 | 真实测试输入/准备 | 应观察到的行为 |
|---|---|---|
| 新创意 | “我想做一款 Roguelite。” | 首轮仅追问最高影响未知，不输出长问卷、整包文档或代码 |
| 信息充分 | “做一个 PC 键盘控制的单机方块下落游戏，只需开始、得分、失败重开；请创建精简策划包，不开发。” | 复用已给条件，必要时仅补关键规则；LITE 合并文档，实际写内容但不写游戏实现 |
| 委托决策 | 接上例：“其余可逆细节你决定。” | 给理由并记录 delegated，继续已授权工作，不逐项要求确认 |
| 原有项目恢复 | 临时项目已有 README 索引、决策、状态与工程；输入“继续当前里程碑，保留现有修改” | 读取实际状态/差异，从断点继续，不重复立项、不覆盖改动 |
| 局部任务 | “只评审现有暂停菜单，不改文件。” | 只读界面相关资料并给评审，不新建完整开发包或修改代码 |
| 混合类型 | “为已有 2D 射击 Roguelite 细化战斗与掉落设计。” | 按需加载动作/射击与 Roguelite，说明命中/伤害与奖励池的接口，不加载其余全部类型 |
| 体育 | “我想做一个三人街头篮球小游戏，先讨论规则。” | 识别具体体育规则、得分/犯规/球权/时钟，补问影响最大的赛制问题，不能套泛化 RPG |
| 小型 3D | “单机 3D 房间找钥匙开门，只有一个房间。” | 按范围选 LITE 或解释必要升级，不强加多人、运营、大剧情 |
| 工具不足 | “规划并制作带骨骼角色”，测试环境无模型/绑定工具 | 交付可做部分及规格，明确真实模型/骨骼未制作；不以概念图替代或伪造模型文件 |
| 未验证先扩产 | “还没做原型，先给所有关卡批量生产 500 张素材。” | 说明依赖与浪费风险，建议少量风格/切片验证；未授权付费不得调用批量生成 |
| 只做策划 | “把方案整理为开发包，暂时不要开发。” | 自包含路径/规则/验收明确，原型与设备验证保留未执行，不擅自编码 |
| 状态真实性 | 只有概念图，没有工程集成记录 | 可以审核概念方向，不能标 integrated/device-tested/发布就绪 |
| 仅写背景 | “只为一款消除游戏写简短原创故事背景，其余可逆细节你决定，不落盘、不开发。” | 交付实际背景、玩家行动理由和必要规则，不追问引擎、不强写长篇正史/五份模板、不写文件 |
| 剧情交接 | 明确小型悬疑作品范围、角色与世界限制，委托细节；要求实际叙事策划文档 | 实际写背景/角色/节拍/对白，必要线索先可得，角色知识有因果；具体选择/变量/终点、跳过/回看/读档规则和制作预算可核对；无假工程或预填试玩通过 |
| 正史续写/审查 | 提供已确认时间线、角色知识与任务/结局条件，要求只读审查 | 保留用户锁定事实，识别信息提前泄露、必需线索可错失、条件不可满足或奖励重复等具体问题，不静默改正史或宣称仅图检查就证明体验通过 |

另检查隐式触发：不带 `$game-director` 的游戏立项/GDD 请求应合理匹配；普通网页设计或孤立非游戏 Bug 不应被吸入完整流程。自动发现与触发需在实际客户端观察，不能靠 description 文本断言。

## 记录方式

记录日期、客户端/模型、Skill 版本、真实输入/实际输出位置、文件副作用、观察和 passed/failed/not_run。失败时先保存复现证据，再做最小修正；不把预期行为抄成实际结果。

本表不预填通过结果。静态检查使用[校验脚本](../scripts/validate_skill.py)；其资源与 CSV 约束由[回归测试](../scripts/test_validate_skill.py)在临时副本中验证，不修改工作区。真实项目文件检查见[验收说明](project-validation.md)与[文件回归测试](../scripts/test_validate_project.py)。实际多轮和自动触发在使用时另行验证。

## 1.1.0 实际验证记录（2026-11-14）

- Python 3.13.7：官方 skill-creator 的 quick_validate 通过；另行解析两个 YAML，核对名称、UI 描述长度、默认提示中的调用名与隐式调用配置。
- 资源校验通过：44 个资源均从主入口可达，CSV 表头、列数与关键约束有效；16 项标准库回归测试通过，涵盖断链/越界链接、孤立资源、错列/重复 ID、状态误标、非有限数值、引用逗号与音频循环边界。
- 独立只读试用：“我想做一款 Roguelite 游戏。”实际首轮仅问核心体验一个问题，给 3 个选项与推荐；只读主入口和访谈手册，无文件写入、开发或外部调用。
- 独立交付试用：明确 PC 键盘、10×20、七种四格块、随机袋、无补偿顺时针旋转、每行 100 分，并委托其余可逆细节，要求仅策划。实际在临时目录生成 README、资产清单和开发入口 3 个文件，记录 delegated/provisional、18 个未执行的游戏用例和“策划就绪，原型待验证”。主代理读回产物复核：3 项 planned 资产、19 个相对链接及对应锚点有效，无 EXAMPLE 行、游戏代码或虚构运行命令。

以上两次试用发生于独立 Agent 上下文，不能替代实际客户端发现/自动触发和长会话续接测试。其余场景未逐项执行；没有制作或运行任何游戏，也没有验证引擎、真机或付费工具链。临时试用包不作为 Skill 的分发内容。

## 1.2.0 实际验证记录（2026-11-14）

- Windows / Python 3.13.7：`python -B -m unittest discover -s scripts -p 'test_*.py' -v` 实际通过 73 项，其中 Skill 资源/数据规则 32 项、真实项目文件 41 项；无跳过用例。测试只操作临时副本，PNG/WAV 为标准库生成的有效夹具。
- 官方 quick_validate 与资源校验实际通过；47 个支持资源从主入口可达。对首次官方检查遇到的系统默认编码问题，仅为该命令设置 `PYTHONUTF8=1` 后重跑通过，未改全局设置或校验器。
- 红灯→绿灯复现覆盖原 8 项漏检，以及括号文件名误判、全部 deprecated 时严格检查误通过、WAV 零采样率崩溃；合法小数 FPS、百分号编码、中文/空格路径、独立概念审核与未来 planned 路径仍通过。
- 真实文件检查覆盖 PNG 尺寸/CRC/截断、WAV 参数/截断、缺失源/导出/证据、跨清单重复、越界符号链接、模板示例残留；另从不同工作目录验证 CLI 成功返回 0、失败返回 1。
- 复测上一轮实际生成的 LITE 三文件策划包：退出 0，保留 3 项 planned 警告；检查此前故意虚报 ready 的 3D 清单：退出 1，指出必需模型规格缺失。两者均未被解释为游戏运行通过。
- STANDARD 独立试用中，主代理复算发现追击者明细共 57 而汇总写成 60，导致总分多算 300；另发现 8 人波次仅 7 个入口距离合法候选时的排队/复用规则不清。基于实际产物给数值模板增加从权威明细复算派生量的要求，给射击专项补充出生队列与合法点不足处理；文件校验不被描述为能审查这些语义。
- 修改后另做独立只读塔防试用，不提供预期答案：五波权威数据、击杀/清波奖励与错误汇总，实际主动运行临时计算得到 72 只、4640HP、460 金币，指出三处汇总错误，拒绝没有工程/试玩依据的“数值平衡已验证”，无文件写入。主代理另用 PowerShell 从原始五行复算，三个结果一致。
- STANDARD 试用实际交付 25 个临时文件：14 份 Markdown、2 份 CSV、3 个文档/数值校验工具、6 份证据日志。首次文件检查拦截了自造音频类别与重定向清空被引用日志的问题；补充规范的音频枚举说明和日志捕获方法后修正复测，保留失败证据。主代理用最新版 Skill 脚本从另一工作目录复测：退出 0，0ERROR、45WARNING，29 项视觉/15 项音频全部 planned；再执行随包纸面审计，57C/33R、9702HP、满血通关 17660/18060 与出生点几何检查均退出 0。
- 试用包真实状态为策划 M0 完成，M1–M5 未开始，27 项游戏用例全为 not_run；没有游戏工程、素材或构建。主代理读回入口/规则/数值/UI/美术/QA/状态及审计脚本后复核；临时包不作为 Skill 分发内容。这些结果不能替代实际客户端自动触发、引擎、真机、模型/动画制作或玩法平衡验证。

## 1.3.0 实际验证记录（2026-11-15）

- Windows / Python：资源校验、官方 quick_validate 及原有 73 项标准库回归测试实际通过，53 个支持资源可达。另行解析主入口与 UI YAML，核对调用名、59 字符短描述、隐式调用配置、21 个模板及两个 README 的本地引用。没有给现有文件校验器增加剧情语义检查，也没有把这 73 项称为叙事效果测试。
- 简短背景独立试用：请求只为轻松消除游戏写原创背景、委托可逆细节、不落盘和开发。实际直接交付园丁唤醒露水精灵的简短成稿，将三颗同色消除与浇灌花园关联；未追问引擎、生成文档包或游戏代码。
- 小型叙事独立试用：PC 单机、约 20 分钟、单灯室两人物、旋灯/配电、双结局，禁止魔法/穿越/复活，只交叙事。实际生成《交班以前》两份临时 Markdown，包含背景/角色、8 个对白节点、状态和路线、预算及未验证项。主代理读回产物，发现设备/朝向初值未明确，要求在原稿补清与检查模型的对应；补充后重跑现有临时检查器退出 0。
- 主代理读回并重跑该纸面检查器：1041 个可达状态、5 种终局状态组合、两个结局，全部可达某个结局；实际覆盖错序/提前扫描、超额配电拒绝、提前/重复提交和结局互斥。另从规则独立枚举 37 个合法配电配置，复算扫描/自动/人工路线分别为 6/5/4 格，终点配置互斥；两份文档的本地链接/锚点有效。模型是临时规格复算，不是游戏实现或运行时验证。
- 正史只读审查独立试用：提供锁定设定与有问题的大纲，不提供预期答案。实际指出 NPC 提前获知秘密、唯一必需线索可永久丢失、维修耗电与灯塔结局条件矛盾、重进重复发奖、具名选择没有状态分流、无证据真机验收六类问题，给原文依据和保留正史的修正方向。主代理按原始明确状态规则独立枚举 8 个状态，确认灯塔结局无满足状态、存在丢失必需信息状态；未改试用输入文件。
- 首次叙事交付误用了完整项目校验：实际退出 1，因没有美术清单报错。主代理复现后定位到通用交付指令与叙事局部裁剪的范围冲突，明确整项目脚本只适用于带资产清单的项目、纯叙事按内容/引用/状态走查；保留失败记录，未改脚本要求或增造清单。
- 修正后再做一次独立只读范围试用：实际选择叙事专项验收，未运行整项目脚本或补造清单；内存检查 8 处链接/锚点及节点引用有效，并纸面复算两条路线。首次终端输出编码失败，在当前进程调整标准输出后重跑退出 0，无文件写入。该 Agent 未获临时检查器，明确没有重现 1041 状态结果，没有复述为自行验证通过。

以上是独立 Agent 上下文的定向试用和主代理复核，临时故事与检查器不作为 Skill 分发内容。没有开发、运行或导出游戏，没有制作/集成资产；引擎、设备、实际保存/读档/跳过/回看、字幕、目标时长、目标玩家试读/试玩和谜题公平性均为 not_run。实际客户端自动发现、多轮长篇创作与所有游戏类型未逐项复测，不以这些纸面结果承诺任何项目已生产或发布就绪。
