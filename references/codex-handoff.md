# Codex / Claude Code 开发交接

使用[开发入口模板](../templates/CODEX_START_HERE_TEMPLATE.md)，替换为项目真实路径与命令。接收方不应依赖原聊天、这个 Skill 或另一台机器的绝对路径。

## 入口必须自包含

记录当前授权阶段、完成目标、MVP/不做清单、已确认规则、文档路径索引、当前里程碑、真实运行/构建方式、外部条件和验收。LITE 合并文档则指向具体章节。首轮完整审计阅读所有适用规格，后续只读相关变更，不重复扫描无关目录。

1. 先核实适用指令、工作目录、Git 状态/差异、引擎/版本、依赖和启动方法，保留用户已有工程。
2. 对照文档与现状列出差异；不能把旧实现自动当需求，不能擅自改变确认规则或删除需求。
3. 只问阻断当前阶段的问题；可逆缺省标为 provisional。明确 App ID、SDK、广告/支付/服务器等未接通条件，不能伪造成功。
4. 未有原型证据时先实现可玩灰盒；有证据则直接推进当前里程碑，不强制返工。代表性视觉/技术切片通过后再扩展内容。
5. 小里程碑编译、运行、测试并保存证据；命令通过不代替关键流程实际操作。
6. 维护进度、测试报告、决策和资产清单；业务变更同步相关规则与用例，按[续接协议](project-continuity.md)保留历史。

核心规则与平台 API 解耦。临时素材明确标记且可替换，不能冒充正式资产。静态页面、固定结果、随机数演示和假联网不能冒充真实游戏机制；设计要求的随机机制本身可以正常使用。

## QA 与退出条件

使用[测试计划](../templates/QA_TEST_PLAN_TEMPLATE.md)和[测试报告](../templates/TEST_REPORT_TEMPLATE.md)。每个关键规则有可复现用例：前置/输入、步骤、预期、实际、环境/构建、证据和缺陷关联。退出阈值按阶段约定，不能在失败后降低标准来宣布通过。

至少按实际功能覆盖核心循环/边界、输入、UI/暂停/失焦、存档/恢复、性能、屏幕适配；联网、广告/付费和多语言只在存在时补充。区分 implemented、compiled、editor-tested、simulator-tested、device-tested、released，缺设备就写 not_run。

S0（数据损坏/重大服务或资金问题）、S1（核心循环无法完成/崩溃）应阻断对应交付；其他缺陷记录影响、规避与是否接受。发布退出标准还包括正式资源/许可、目标平台与必要设备验证；有未验证项时报告实际状态。

最终交付工程位置、引擎版本、启动/构建方式、已完成与未完成、验证结果和已知问题。本地提交遵循项目授权；远程推送、发布、付费调用及删除/覆盖现有工作不会由交接文档自动授权。
