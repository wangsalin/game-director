# 自适应立项访谈

## 如何开始与停止

先提取用户消息及已有 Brief 中的答案。新创意从最影响下一步的未知项开始；已有需求只补缺口，局部任务不做整套访谈。每轮一个关键问题；给选项时附简短的推荐理由。

访谈不是固定问卷。用以下维度发现依赖关系：

| 缺失维度 | 什么时候优先问 | 可用问法 |
|---|---|---|
| 核心体验 | 只有类型名，没有玩家行为 | 玩家反复做的那件事，你最想让他体验到什么？ |
| 平台/输入 | 操控、性能或渠道会改变玩法 | 先做手机触屏、PC 键鼠，还是双端？ |
| 联网边界 | 提到对战、社交、共享经济 | 需要实时同场对战，还是排行榜/异步互动？ |
| 单局与成长 | 不清楚循环终点和重开动力 | 一局结束后，哪些东西保留？ |
| 范围/资源 | 内容量与工期明显不匹配 | 首版先证明哪个体验？现有团队和可投入时间是多少？ |
| 美术方向 | 已准备画原型或资产 | 更看重清晰辨识、叙事氛围，还是写实表现？ |

其余按需要覆盖：受众、语言、2D/3D/镜头、横竖屏、商业化、离线、关卡量、操作和无障碍、引擎偏好、现有工程/素材、预算和期限。不相关的问题跳过。

**停止条件**：核心体验、平台/输入、MVP 和影响方案的约束足够明确，可以写出短 Brief。美术细节、次要数值可先标为假设，不为填表继续追问。

## 决策语义

- `confirmed`：用户明确给出或确认的决定。
- `delegated`：用户已说“你决定”，在其授权范围内由制作总监选定；说明理由后继续，不再把每个可逆细节退回确认。
- `provisional`：信息不足时的可逆临时假设，有验证方式和截止阶段。
- `open`：尚未决定；只有阻断当前工作或涉及重大方向/费用时才提问。
- `superseded`：被后续决定替代，保留原记录与替代 ID。

“你决定”不代表授权购买、批量付费生成、发布或丢弃工程。低风险细节可委托，重大不可逆操作按任务授权边界执行。

## 访谈记录与恢复

只读讨论时在对话内维护简短的“已确定 / 假设 / 待定”摘要。用户要求创建项目文档后，写入 Brief 和决策记录；具体恢复入口见[续接协议](project-continuity.md)。已有答案不重复问，有冲突先指出冲突及其影响。

每形成一个有意义的方向结论，概括锁定内容和下一项关键未知；不必每轮复述整张表。用户临时询问问题时直接回答，再继续原任务。

## 参考游戏研究

研究官方商店、开发者资料和公开演示，记录 URL、查阅日期、支持的结论；玩家评价只能作为特定样本，不能冒充市场统计。明确事实、推断与未知，不能声称实际试玩过未玩的游戏。

拆解核心循环和体验后设计原创表达。未经授权不复制源代码、商标、角色、音乐、文本或专有素材。用户要求“复刻”时，说明可以保留的玩法目标与需要原创的表达，不用冗长版权问卷阻断正常设计。
